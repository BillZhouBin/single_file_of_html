## 一、美学方向（Design Direction）

### 1.1 定位：**三国古战场 × 像素割草**

「割草」这个词本身就是从三国无双来的——一人对千军的爽感。所以本作没有沿用品类常见的丧尸 / 史莱姆 / 太空题材，而是**回到词源**：

| 常见做法 | 本作选择 | 理由 |
|---------|---------|------|
| 暗黑哥特 / 霓虹赛博 | **青绿草地 + 朱红铠甲 + 鎏金** | 与合集已有的「深空蓝紫」（飞机大战）、「糖果色」（兔子赛车）、「喜庆红金」（聚宝盆）拉开色相带，避免五款游戏摆在一起撞脸 |
| 丧尸 / 史莱姆 | **步兵 / 弓手 / 骑兵 / 盾兵 / 敌将** | 兵种差异自带可读性，无需额外图形语言玩家就能预判威胁 |
| 魔法 / 科技武器命名 | **偃月刀 / 飞刀 / 雷霆 / 火焰 / 冲撞 / 毒瘴** | 冷兵器 + 天象，符合武将设定且直觉可懂 |

### 1.2 三条美学原则

1. **暖主角 / 冷背景**：玩家永远是「朱红 + 鎏金」暖色块，战场是青绿冷底 —— 千军万马里主角永远一眼可辨，这是割草类游戏的**第一可用性红线**。
2. **可读性 > 华丽**：同屏峰值 220 个敌人，任何复杂描边/渐变都会变成糊状噪点。故敌人统一用 **8×8 极简精灵 + 单色块区分兵种**，把视觉预算全留给「玩家 + 特效」。
3. **字重即层级**：不用任何图片资源，所有层级靠**字号 + 字重 + 颜色**三变量表达（详见 §2.2）。

**差异化记忆点**：朱红兜鍪武将 + 金色偃月刀弧光 + 满地鎏金经验珠 —— 一套「一人屠一军」的暖色主角语言。

### 2.2 字体系统

```css
font-family: ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

> **与合集的刻意差异**：其余 5 款游戏用 Google Fonts 的 `Press Start 2P` / `VT323`。本作**不引用任何外部字体**，全用系统等宽栈。
> **理由**：割草类同屏信息密度极高（HUD 芯片、武器栏、升级卡、飘字同时存在），`Press Start 2P` 在 10–13px 会糊成一团；且本作升级卡需要在**短暂暂停**内被快速阅读，可读性优先级高于风格一致性。代价是标题少了一点"街机味"，用**字重 700 + letter-spacing 3px + 硬投影**补偿。

| 角色 | 字号 | 字重 | 字距 | 用途 |
|------|------|------|------|------|
| 覆盖层标题 | `clamp(26px, 7.5vw, 44px)` | 700 | 3px | 「一骑当千」/「败北」/「功成」 |
| 结算分数 | 44px | 700 | — | `res-score` |
| HUD 芯片 | 13px | 700 | 1px | `Lv` / `0:00` / `斩` |
| 卡片正文 | 13px | 700 | — | 玩法说明行 |
| 卡片小标题 | 15px | 700 | 1px | 「玩法说明」 |
| 升级卡名称 | 15px | 700 | 1px | `lv-name` |
| 升级卡描述 | 12px | 700 | — | `lv-desc` |
| 按键提示 | 11px | 400 | 1px | `hint-key` |

### 2.3 间距系统（4px 网格）

```
4 / 6 / 8 / 10 / 12 / 14 / 18 / 20 / 26 px
```

关键落位：覆盖层 padding `26px`；卡片 padding `18px 20px`、圆角 `18px`；升级卡 padding `12px 14px`、圆角 `14px`、卡间 `gap 10px`；按钮 padding `14px`、圆角 `12px`；HUD padding `10px 12px`、芯片圆角 `999px`。

**圆角策略**：容器级 `12–18px`（柔和现代），指示器级 `4–8px`（武器槽/等级角标），状态类 `999px`（芯片/胶囊）—— 三级圆角避免"处处一样圆"的廉价感。

### 2.4 动效规范

- **缓动**：统一 `ease`/`linear`，**禁用回弹与弹性**（避免廉价感）。覆盖层 `opacity .2s`；血条/经验条 `width .12s linear`；卡片 hover `transform .1s`。
- **屏幕震动**：`shake` 为像素值，逐帧 `shake -= dt*22` 线性衰减，渲染时 `translate(rand(-shake,shake))`。
  - 受击 `7` / 敌将阵亡 `10` / 落雷 `4`。
- **按钮按下**：`translateY(3px)` + 硬阴影从 `6px` 收到 `2px`（模拟实体按键）。
- **经验珠**：`3 + sin(t*7)*0.8` px 呼吸，大颗（v≥8）用 `#fff3b0` 区分。
- **尊重 `prefers-reduced-motion`**：关闭 `.overlay` / `.lv-card` / `.btn` 的 transition。**注意**：Canvas 内的屏幕震动属玩法反馈，保留（去掉会让受击失去感知）。

### 3.3 武器栏 `#wbar`（底部居中）

- 34×34 圆角槽位，`gap 6px`。
- **武器槽** = 武器主色实底 + 白色单字图标（刀/镖/雷/焰/冲/毒）+ 右下角金色等级角标。
- **被动槽** = 深色底 + **被动色描边**（战靴绿 / 神力红 / 疾风冰蓝 / 磁石金 / 护甲灰 / 回春橙）+ 同款等级角标。
- 区分逻辑：**实底=主动，描边=被动** —— 无需读字就能分清两类构筑。

### 3.4 升级三选一 `#levelup`（核心界面）

```
        突破 · 择一精进
┌───────────────────────────┐
│ [焰] 火焰         [新]      │  ← 42px 图标 + 名称 + NEW 角标

└───────────────────────────┘

└───────────────────────────┘

│ [雷] 雷霆         [新]      │

```

- 竖向三卡，**无确认按钮**（点击卡片即生效并继续）—— 割草节奏要求零摩擦。
- `NEW` 标签红底白字（新获得），已有项金底褐字显示 `Lv N`（升级）。**同一枚角标两种语义**，靠颜色区分。
- hover/focus 上浮 `2px` + 描边转红；`:focus-visible` 可键盘操作。

### 3.5 暂停 `#pauseOv` / 结算 `#overOv`

- 暂停：标题「整军待发」+「继续 ▶」/「收兵回营」（红色次按钮）。
- 结算：标题「败北」/「功成」+ 破纪录金色胶囊 + 44px 总分 + 四行虚线分隔数据（斩敌 / 存活 / 等级 / 历史最佳）+「再战 ▶」/「回主菜单」。
- 计分公式：`round(斩敌×10 + 等级×50 + 存活秒×2 + (通关 ? 500 : 0))` —— **等级权重最高**，鼓励活下去而非无脑冲杀。

### 3.6 触摸输入

- **虚拟摇杆**：104px 圆，`rgba(10,14,26,.34)` 底 + 金描边；46px 金色摇杆头，跟随触点。左下 `left:26px / bottom:62px`，避开武器栏。
- 仅触摸端显示（`.stick.show`），键盘输入时不出现。

## 四、像素精灵规范

**设计要点**：兜鍪占头部 7 列（够大才像武将），朱红盔缨做**唯一垂直向上的暖色尖**（在绿色战场上是最强识别点）；偃月刀画在右侧独立列，与人物身体分离，保证挥砍时的旋转动画不会糊在一起。

## 五、渲染与性能

### 5.1 分辨率策略

```js
var BASE_H = 540;            // 逻辑高度锁定（横屏，高度优先）
var W = 960, H = BASE_H;     // 逻辑分辨率（横屏 16:9 基准）
var WORLD_W = 3400, WORLD_H = 2400;   // 战场为横长方形，匹配横屏视野比例
const W_MIN = 720, W_MAX = 1400;      // 逻辑宽度夹取区间，防极端比例失真

function resize(){
  var r = cvs.getBoundingClientRect();
  var cw = r.width, ch = r.height;
  H = BASE_H;
  W = clamp(round(H * (cw / ch)), W_MIN, W_MAX);  // 宽度按容器真实长宽比推导
  dpr = min(devicePixelRatio, 2);
  cvs.width  = round(r.width  * dpr);
  cvs.height = round(r.height * dpr);
  scale = min(cvs.width / W, cvs.height / H);
  offX  = (cvs.width  - W * scale) / 2;   // 极端比例下居中（letterbox）
  offY  = (cvs.height - H * scale) / 2;
}
ctx.setTransform(scale, 0, 0, scale, offX, offY);
ctx.imageSmoothingEnabled = false;
```

- **横屏优先**：`#game` 容器 `width:100dvw / max-width:1400px`、`height:100dvh / max-height:780px`——手机横屏满铺**零黑边**，桌面封顶 1400×780 居中。逻辑高度锁死 540，宽度按容器真实长宽比在 `[720, 1400]` 内推导，保证不同机型视野一致且不变形。
- 极端比例（超宽 21:9 / 接近正方 / 极矮）由 `offX/offY` 居中 letterbox 兜底，绝不拉伸。
- `image-rendering: pixelated` + `imageSmoothingEnabled = false` 保证像素硬边。

### 5.2 三条性能红线

1. **精灵预烘焙**：`bake(mtx, pal, scale)` 在启动时把字符矩阵画进离屏 canvas，运行时只 `drawImage`。**禁止逐像素 `fillRect`**（220 敌人 × 64 像素 = 14k 次调用/帧，必掉帧）。
2. **空间网格加速**：`CELL = 64` 的 `Map<cellKey, enemy[]>`，索敌/碰撞只查邻近 9 格，把 O(n²) 降到近似 O(n)。
3. **视口裁剪**：所有实体绘制前先做屏幕矩形判定，屏幕外直接 `continue`；地形只遍历可见格子（`drawGround` 按 `ts=48` 对齐取可视区间）。

### 5.3 地形（棋盘格 + 哈希点缀）

```js
h = hash2(wx, wy);                    // 确定性伪随机
fillStyle = h < 0.5 ? grass1 : grass2; // 棋盘格
if (h > 0.80) 画 4×4 的 grass3 草丛;
```

用 `hash2`（`sin(x*127.1+y*311.7)*43758.5453` 取小数）而非 `Math.random()` —— **同一格每帧颜色恒定**，否则会闪烁；且无需存储地形数组。战场边界用 `rgba(122,74,42,.55)` 6px 木栅线。

## 六、音频设计（程序化 Web Audio，零资源）

`tone(freq, dur, type, vol, slideTo)`：方波/锯齿/正弦 + 指数衰减包络 + 可选滑音。

| 事件 | 音色 | 参数 |
|------|------|------|
| 斩杀 `kill` | square | 180→90Hz，70ms，音量 .035 |
| 命中未死 `hit` | square | 300→200Hz，40ms，.02 |
| 拾取 `pick` | sine | 880→1180Hz，45ms，.03 |
| 受击 `hurt` | sawtooth | 140→60Hz，180ms，.06 |
| 升级 `level` | square | 520→660→880Hz 三连音（90ms 间隔） |
| 落雷 `thunder` | sawtooth | 90→40Hz，220ms，.05 |
| 冲撞 `dash` | square | 240→520Hz，120ms，.04 |
| 结束 `over` | square | 300→200→120Hz 下行三音 |
| 敌将登场 `boss` | sawtooth | 110→70Hz，350ms，.06 |

**设计原则**：高频事件（斩杀/命中）**极短（40–70ms）+ 低音量**，因为一秒可能触发十几次；低频事件（升级/敌将）才给足时长与音高变化。上行音=正反馈，下行音=负反馈。`M` 键全局静音。

**限流护栏（2026-09 新增）**：火焰/毒瘴/弹幕在后期每帧对几十个敌人结算伤害，若每个命中都发声，每秒会产生数百上千个振荡器 → 重叠方波互调成持续的"兹拉"底噪。故高频音经 `gateSfx(name, gapMs)` 全局节流：`hit`≥80ms、`kill`≥45ms、`pick`≥55ms 才放行一次。低频事件音（升级/落雷/冲撞/敌将）各自有冷却间隔，不需额外限流。

## 七、玩法数值设计（平衡表）

> 设计系统不只管外观——在 roguelike 里**数值曲线本身就是体验设计**。

### 7.1 成长曲线

- **升级所需经验**：`expNeed = round(5 + level*4 + level^1.35)`，初始 5。
  （Lv1→2 需 10，Lv5→6 需 34，Lv10→11 需 68 —— 线性项保证前期爽快，幂项防止后期失控）
- **升级来源**：武器与被动**共享同一个三选一池**，每级随机抽 3 张。武器上限 5 级（6 种），被动上限 5 级（6 种）。
  > 这是本作 roguelike 性的核心：**同一套选项池，每局抽出不同组合**。

### 7.2 压力曲线

- **生成率**：`rate = 1.5 + elapsed × 0.020` 个/秒（0s 时 1.5/s，60s 时 2.7/s，180s 时 5.1/s），同屏上限 220。
- **兵种解锁权重**（随时间线性/封顶递增）：

| 兵种 | 起始 | 权重公式 | 封顶 |
|------|------|---------|------|
| 步兵 foot | 0s | `max(1, 60 - t*0.18)` | 递减 |
| 弓手 arch | 25s | `min(26, (t-25)*0.30)` | 26 |
| 骑兵 rider | 45s | `min(30, (t-45)*0.34)` | 30 |
| 盾兵 shield | 80s | `min(24, (t-80)*0.24)` | 24 |

- **敌将**：每 60 秒固定 1 名（与生成率解耦，形成"节拍器"式的高压节点）。

### 7.3 手感常量

| 参数 | 值 | 说明 |
|------|-----|------|
| 玩家生命 / 移速 / 半径 | 120 / 172 px/s / 15 | |
| 受击无敌 | 0.65s | 给玩家脱离包围的窗口 |
| 冲撞附带无敌 | 0.26s | 冲撞=位移+伤害+短无敌，是唯一的主动脱身手段 |
| 拾取半径 | 70 × 磁石倍率 | |
| 生成距离 | 屏幕矩形外缘切线 + `rand(10,70)` | 见下 |

> **生成位置的坑**：若用屏幕**对角线**半径生成，远端敌人要飞 10 秒才到 —— 开局极度冷清。改为沿**屏幕矩形外缘**的切线半径（`min(halfW/|cos|, halfH/|sin|)`），保证既不在视野内凭空出现、也不会远到干等。（横屏下 `halfW > halfH`，敌人主要从左右两轴进入，符合单骑冲阵的包抄感。）

> **刀刃判定的坑**：环绕类武器若在**圆周**上做点距离判定，敌人贴身（距离≈0）时圆周永远扫不到，会出现"明明砍到了却 0 击杀"。本作改用**以玩家为圆心的扇形 + 随距离放大的角容差**：`tol = atan2(20, max(dist, 14))` —— 越近容差越大，贴身围杀必中。

### 7.4 武器与被动（完整数值见 `README.md`）

- 6 武器：偃月刀（环绕切割）/ 飞刀（追踪穿透）/ 雷霆（随机落雷）/ 火焰（扇形持续）/ 冲撞（位移脱身）/ 毒瘴（地面区域）
- 6 被动：战靴 +10% 移速 / 神力 +15% 伤害 / 疾风 +12% 攻速 / 磁石 +28% 拾取 / 护甲 +22 生命上限 / 回春 +0.6 HP/s（均为每级）

## 九、与合集的一致性 & 刻意差异

**遵守**：单文件零依赖、**横屏 16:9（手机横屏优先、零黑边）**、键盘 + 触摸双输入、无限/限时双模式、`localStorage` 持久化最佳分、程序化 Web Audio、`prefers-reduced-motion`、空格/Enter 快捷开始、竖屏自动提示「请横屏」。

**刻意差异**（及理由）：

| 项 | 合集惯例 | 本作 | 理由 |
|----|---------|------|------|
| 字体 | Google Fonts 像素体 | 系统等宽栈 | 同屏信息密度最高，像素体在 10–13px 不可读 |
| 画布比例 | 240×400 / 类似 | 动态 16:9（基准 960×540，宽随设备长宽比推导，夹取 720–1400） | 割草需要更大的横向可视范围来预判包抄 |
| HUD 位置 | 顶部一行 | 顶部三条 + 底部武器栏 | 信息量本身更大（经验/生命/Boss/等级/时间/斩敌/构筑） |
| 主色 | 各游戏不同 | 青绿 + 朱红 + 鎏金 | 色相带避让，五款并列不撞脸 |

**持久化键**：`localStorage['yiqidangqian_best_<mode>']`（`mode` = `infinite` / `timed`，两种模式分别记录最佳分）。
